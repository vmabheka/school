Auto-Sync & Access Point Integration

Automatically sync when internet is detected. The Access Point Monitor runs in the background, checking connectivity periodically and triggering a full sync as soon as the online server is reachable. This works even when nobody is using the system — the monitor runs as a background service.

Access Point Monitor active — checking connection periodically...
How the Access Point Monitor works:
  1. HTTP Ping — Checks if the WordPress sync endpoint is reachable
  2. DNS Check — Falls back to resolving Google's DNS (8.8.8.8) if endpoint is down
  3. NetworkManager D-Bus — On Linux, detects WiFi/access-point state changes directly
  4. When connectivity is detected, auto-sync pushes pending changes and pulls online updates
  5. Sync storms are prevented — at least 60 seconds between auto-syncs
  6. Settings are persisted to database — survive app restarts

How Sync Works

One-Button Sync: Click "Sync Now" to push all local changes to WordPress and pull any new data back. This is the recommended way to sync manually.

Access Point Monitor: A background thread that continuously checks if the internet is available via your school's network access point. When it detects connectivity, it automatically triggers a full sync. This works even when no one is logged in.

Auto-Sync: When enabled, the Access Point Monitor automatically detects when internet is available and triggers a full sync. Perfect for schools that go offline and reconnect periodically. Settings are saved to the database and persist across restarts.

Export/Import: For environments with no direct connection, export a complete JSON snapshot containing academic years, classes, people, finance, exams, accommodation, timetables, and communication data, then upload it to the online system.

Conflict Resolution: When both systems have modified the same record, the newest change wins (timestamp-based). Sync storms are prevented by enforcing a 60-second minimum between auto-syncs.
